# 统一参数与持久存储

飞机编号是 EEPROM 参数，总数量在 `src/config/aircraft_config.h` 通过编译宏 `COFLY_AIRCRAFT_COUNT` 设置（默认 3，支持 1/3/4/5/7），不进入参数列表或持久存储。同一数量、硬件、接收机及控制算法配置下，A～G 可以刷同一个固件，只需逐机设置编号。

## 第一次使用

1. USB 连接地面站，在“飞机设置 → 参数”读取参数。
2. 设置 `aircraft_id`，1=A，2=B，…，7=G，编号不得超过固件的 `COFLY_AIRCRAFT_COUNT`。单机将宏设为 1 后重新构建，编号设为 1。
3. 使用通讯连接页“重启飞控”或断电重启，重新连接并读取参数，确认本机身份。
4. 完成 IMU 校准，确认 `imu_calibration_valid=1`。没有有效身份或 IMU 校准时禁止解锁。

新板的编号默认 0（未配置）。保存身份只改变待启动值，主循环使用启动时锁定的身份；运行中改编号不会改变串口路由或控制分配。总数量是编译期常量，修改数量需要重新构建并刷入固件；编号参数的最大值随宏变化。已保存编号超过新数量时回到 0 未配置，其他兼容参数继续恢复。

`COFLY_AIRCRAFT_COUNT=1` 选择单机混控，本机 IMU 滚转角及角速度作为反馈，停止构型控制与机间收发，其他支持的数量使用编队控制路径；单机/编队由该数量宏统一选择。所有飞机均调用 `logFlightData()`，使用同一 CSV 表头及字段顺序。

单机和多机使用同一套参数声明、默认值与存储。已保存的参数按名称和类型恢复；没有保存值时使用注册变量的初始化值。重新构建不同飞机数量的固件不会因数量变化重置或替换控制增益。

## 参数声明

在 `src/parameters/parameter_registry.cpp::flightParameterTable()` 一处注册。固件参数的声明、注册、编解码、存储与服务集中在 `src/parameters/`，文件职责见[参数模块说明](../src/parameters/README.md)。控制增益、滤波、限幅及执行器方向/trim 的变量和默认值集中在 `src/parameters/control_parameters.cpp`；身份、传感器和校准变量仍归各自模块所有。控制算法通过 `src/parameters/control_parameters.h` 直接读取同一份 RAM 参数，积分、指令滤波及 INDI 延迟队列由 `control/` 下各控制器对象持有，外部诊断结果由 `control/control_output.h/.cpp` 按控制器持有，模式由 `control/control_modes.cpp` 管理。

```cpp
{1001, "aircraft_id", &aircraftIdParameter, 0, COFLY_AIRCRAFT_COUNT, "Aircraft", "Identity",
 ParameterStorage::EEPROM, ParameterEffect::Reboot},
```

每条声明包含内部 ID、名称、变量地址、范围、分组、说明、存储介质、生效时机和只读标记。浮点参数绑定 `float`，整数参数绑定 `int32_t`；省略最后的选项时默认 SD、立即生效、可编辑。

五路输出的软件 PWM 上下限为 `pwm_servo1_min_us` / `pwm_servo1_max_us` 至 `pwm_servo5_min_us` / `pwm_servo5_max_us`，均为整数，属于 Actuator 组，保存到本机 SD 卡，默认每路 1000～2000 μs。锁定状态下可修改，接受后立即生效并按 2 秒合并保存机制写入 `params.cfg`；重启恢复，不写入 EEPROM。每路须满足驱动范围内的 `min <= max`，允许相等；非整数、非有限、越界、上下限倒置或解锁状态下的修改被拒绝，不改变 RAM。旧 SD 文件没有这些字段时使用默认值并补入新快照；完整加载后统一检查上下限，不依赖记录顺序，发现倒置时五路软件范围整体恢复默认并迁移保存，其余参数继续恢复。通道3同时约束 INDI 的 PWM 和推导舵角，公式见 [俯仰 INDI](indi-variable-naming.md#配平零点与线性换算)；锁定与输出行为见 [固件指南](firmware-guide.md#执行器锁定与限幅)。

修改存储位置只需改 `ParameterStorage::EEPROM` / `ParameterStorage::SD`。两种介质均以名称和类型匹配，内部 ID 仅用于模块查找，不写入新记录。新增参数用新名称及未使用的内部 ID，变量初始化值作为默认值。改表顺序或内部 ID 保留已有值；改名视为新参数，使用默认值；类型变化、超界旧值单项回默认值。删除的旧项在成功保存当前快照时移除，不设置删除状态。

参数名称上限在 `src/parameters/parameter_storage_config.h` 的 `COFLY_PARAMETER_NAME_LIMIT` 配置，默认 **27**，可用 `-DCOFLY_PARAMETER_NAME_LIMIT=48` 覆盖；范围 1～128，名称只能包含 ASCII 字母、数字、下划线，超长拒绝初始化，不截断。

记录采用参考提交 e419d682 的 `名称:类型=数值` 文本形式，每条以 LF 换行。名称不补零；结束符只用于 RAM 字符串缓冲，不写入介质。类型为 `float` 或 `int`。float32 使用可还原同一原始位模式的最短十进制，并展开科学计数法；int32 使用十进制整数。读取校验类型、有限值、范围、重复名称及记录数量。数值缓冲 64 字节，兼容记录缓冲 201 字节；这不是固定记录宽度。

目前共 120 项：109 项在 SD（含五路 PWM 上下限及立即生效的 USB 调试开关）；11 项在 EEPROM，包括飞机编号、6 个 IMU 零偏、校准有效标记、校准模型标记、整组指纹和 MT6701 测量零点。校准有效/模型/指纹三个字段只读，固件整组管理；手工改零偏会使校准失效。当前 BMI088 零偏仍绑定原 `*_6050` 字段名，保持既有测量轴映射。

所有标记 `ParameterEffect::Reboot` 的参数仅能在锁定状态下修改。接受不同值并更新 RAM 中的待启动设置后，统一参数服务立即锁存“待重启”状态：OLED 全屏显示英文 `REBOOT REQUIRED`，禁止解锁并保持执行器安全位置；改回原值也不会解除，只有重启清除。相同值或被拒绝的修改不触发；延迟保存失败不解除锁定。

新增其他重启参数时，使用它的模块也需要像 `aircraft_config.cpp` 一样锁定启动值，不能在控制周期直接使用可修改变量。

## EEPROM 与 SD 的区别

USB 修改和电脑文件导入在验证通过后先更新 RAM，返回 `PENDING`。EEPROM 与 SD 各自维护待保存状态：该介质最后一次实际数值变动后等待 **2000 ms**，再合并保存一份完整快照；新变动只重置对应介质的计时，相同值、无效输入不重置。只比较新值与当前 RAM 值，不维护已保存值副本；RAM 实际变化就将该介质置为 dirty，即使改回原值也仍在最后变动后保存。`SAVED` 的命令确认表示该介质没有待保存变动（已保存或本次无需写入）。即使 USB 断开，主循环仍执行延迟保存。

存储写入或读回校验失败时保留 RAM 与待保存状态，间隔 2 秒重试；两种介质独立处理，一种失败不会阻止另一种保存。USB 异步通知 `STORAGE / SD|EEPROM / SAVED|FAILED`，地面站显示合并保存结果。保存完成前断电可能丢失待保存值。地面站重启命令会强制保存全部待写入值，失败则取消重启。

完整 IMU 校准先验证整组零偏，在 RAM 中同时更新零偏、模型、指纹及有效标记，再与普通参数共用 dirty 和 2 秒延迟保存；不会提前刷新其他待保存修改，也不执行分阶段写入。没有实际变化的校准组不重置计时，保存失败保留已生效的 RAM 校准并重试。手工修改单项零偏仍立即使 RAM 校准有效标记失效，并随对应介质快照保存。启动加载和迁移保持原有同步流程。

SD 通过文件系统读写文件；Teensy 4.1 的 EEPROM 接口使用固定逻辑地址，底层由芯片 Flash 仿真。两者均不应在控制循环每周期读取持久存储：开机加载到 RAM，控制运算只读 RAM；仅用户保存或校准时写入。

EEPROM 使用固定主槽和备份槽，各 2048 字节，起始地址 128 和 2176，要求 `EEPROM.length() >= 4224`。两槽保存与 SD 文件完全相同的 V8 文本容器；0～127 不使用。主槽有效时优先加载；无效才读取备份。两槽都无效时 EEPROM 参数使用默认值，身份未配置、校准无效；SD 独立加载。

两种介质共用 `src/parameters/parameter_text.h` 的容器校验和 `src/parameters/parameter_record.h` 的数值转换/记录编解码。格式为 ASCII、LF，无 BOM：

```text
COFLY_PARAMS_V8
COUNT=2
gain:float=0.25
aircraft_id:int=2
CRC32=xxxxxxxx
```

头部包含版本行和数量行，长度为 `22 + 数量十进制位数` 字节；例如 17 或 59 项时为 24 字节。每条记录长度随名称、类型和数值变化，尾部 `CRC32=八位十六进制加 LF` 共 15 字节，覆盖此前全部文本。不包含 ID、代次、板卡名称、删除状态、名称宽度或额外完成标记。位置不再通过固定步长计算，每次合并保存仍重建完整快照。

保存时先备份经过校验的旧主数据，确认备份写入成功后再更新主数据。从备份恢复时保留备份，直接修复主数据。EEPROM 写槽时先将普通版本头的首字节置为零，使该槽暂时无效；写入并验证其他文本及 CRC 后，最后恢复首字节，再逐字节校验。没有额外的持久化标记字段，EEPROM 和 SD 内容完全一致。EEPROM 主槽内容相同时可跳过实际写入，从备份恢复则修复主槽。

参数表变化并不等于整槽失效：槽的格式/CRC 合法后，逐项以名称、类型和当前范围恢复。新项或不兼容项单独使用默认值。整个存储格式版本不识别或两个槽均损坏，才全表回退。

SD 使用 `params.cfg` 与 `params_backup.cfg`，电脑导入/导出的 `.cfg` 也采用相同 V8 文本容器，不包含板卡 UID 或宏配置。存储介质不影响记录布局；同一组参数及顺序下，EEPROM 与电脑 SD 编码的字节完全一致。文件验证完整后再恢复；保存后读回校验。USB 参数命令仍用文本，持久存储与 USB 共用数值文本转换。

## 当前占用与容量

有效占用随数值文本长度变化，不能用“每条 32 字节”计算：单份占用为头部 + 全部记录行 + 15 字节 CRC 尾部。

| 介质 | 容量限制 |
| --- | --- |
| EEPROM | 主备槽各 2048 字节；有效文本最多 2047 字节，编码需留一个 RAM 结束符字节 |
| SD | 整个参数表最多 512 项；文件须小于 103168 字节，与 SD 卡物理容量无关 |

EEPROM 两槽仍预留 4096 字节，Teensy 4.1 EEPROM 库暴露 4284 字节，0～127 和 4224～4283 不使用。记录数量上限取决于实际名称及数值长度；超出槽容量时在写入前拒绝，保留旧快照。

SD 文件缓冲为 `512 * (128 + 64 + 9) + 256 = 103168` 字节，约 100.75 KiB 静态 RAM。名称上限只影响注册及导出验证，不造成名称字段填充。

## 格式与介质迁移

仅支持当前共享文本 V8，不读取 V7 二进制及不同版本头的旧文本快照。没有有效快照时使用默认值；升级后重新设置编号、零点并完成 IMU 校准，数量仍由编译宏决定。

已删除的 `indi_pitch_pwm_to_deg_b`、`indi_pitch_defl_min/max`、`indi_pitch_pwm_min/max` 按未知参数跳过，不再参与控制；成功保存当前快照后移除旧记录。升降舵逻辑方向变化不会自动翻转已保存的 `pwm_channel3_rev`，升级步骤见 [方向迁移](firmware-guide.md#执行器映射与方向迁移)。校准指纹或模型不兼容时需重新校准，不能仅凭旧有效标记继续使用。

改存储介质后，从当前目标介质优先读取；目标尚无对应项时可读取原介质。先保存并验证目标，再重建原 EEPROM 快照以移除迁移副本。SD 保存失败时，EEPROM 中的源记录继续保留，仍占用容量；没有删除状态。容量不足或迁移失败不会静默丢弃旧项，需处理 `EEPROM_ERROR` / `MIGRATION_PENDING`。

统一的是参数记录和处理规则，外层保护适配介质：SD 使用主/备文件，EEPROM 使用主/备槽，容器和 CRC 完全一致；两种介质均主数据优先、失效回退备份、两份都失效才使用默认值。均不携带代次或单独的完成标记。

校准零偏、模型、指纹、有效标记必须位于同一介质；当前全部位于 EEPROM，也支持将整组改为 SD。注册表初始化发现拆分到不同介质或缺少字段时拒绝启用参数服务并打印原因，不再保留跨介质校准排序状态。整组数据随同一份主备快照保存，容器 CRC 保护完整写入；校准指纹继续校验零偏和模型，缺少字段或校验失败则视为未校准。SD 拥有的校准字段缺失时，已经移除的 EEPROM 源记录不能证明当前校准有效。

EEPROM 写入和 SD 写入都可能阻塞；身份/校准修改要求锁定。本版没有在真机测量所有构型的最坏周期时间；统一固件会保留所有机型分支，代码体积增加，少量 RAM 判断开销需要板上检查 500 Hz 时序。

历史主机模拟检查曾覆盖主备恢复、写入中断、合并保存、失败重试、整组校准、计时器回绕和 USB 断开后保存。相关临时测试与数值产物已清理，不作为本次重新验证的结果；实板 Flash 仿真层断电行为仍需单独验证。验收目标见 [软件需求](requirements.md)，历史证据边界见 [研究与历史](archive/CONTROL_ARCHITECTURE_ANALYSIS.md#历史检查的证据边界)。
