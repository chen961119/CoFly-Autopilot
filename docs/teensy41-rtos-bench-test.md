# Teensy 4.1 FreeRTOS 真板测试单

本轮验证一次性 `Startup` 对五个业务任务的交接，以及发布固件在真实外设负载下的 2 ms 控制周期。以下次数、时长和零增量目标供本轮台架验收使用。每项记录「通过 / 异常 / 未测」和证据文件名。

## 台架准备

- 拆桨，断开电调、舵机动力，只给飞控、已连接的传感器和接收机供电。测量仪器与飞控共地。准备一张可写测试 SD 卡，备份原卡和地面站参数，记下五路原始 trim、调试参数、飞机身份和 IMU 校准状态。
- 烧录当前工作区生成的 `teensy41` 发布固件，登记 HEX 的 SHA-256、板号、SD 卡、接收机和外设。断点测试单独使用 `teensy41_debug`。记录实际加载的固件可区分同一提交上的本地改动。
- 建议准备示波器或逻辑分析仪。D2、D3、D4、D5、D6 依次对应左副翼、右副翼、升降、油门、方向。通道不足时，优先同时捕获 D2（测试标记）和 D5（实际油门 trim），分次复测其余通道。缺少仪器时把物理脉宽项记为「未测」。
- 使用地面站的参数页或串口助手。直接发命令时使用 ASCII、LF 结尾，每条请求使用独立 ID。下面前四条依次查询能力、身份与配置、实时状态和完整参数，第五条开启周期诊断。

```text
GCS CAPS 1
GCS CONFIG 2
GCS DATA 3
PARAM READ 4
PARAM SET 5 usb_loop_rate_debug 1
```

在 `CONFIG` 中核对 `aircraft_id` 和 `config_valid`，在 `DATA` 中核对 `locked`，在 `PARAM READ` 中核对存储状态和 `imu_calibration_valid`。记录诊断参数原值。实际修改 SD 参数后，等待 `STORAGE SD SAVED` 或参数页确认保存，再做断电测试。[地面站操作](../tools/ground_station/README.md) · [参数协议](../tools/ground_station/PARAMETER_PROTOCOL.md)

## 第一轮：发布固件，单板必测

| 项目 | 操作 | 建议通过条件与证据 |
| --- | --- | --- |
| 1. 冷启动、参数恢复与首枚 PWM | 锁定时，选一个非油门通道（如 D2），把 trim 设成当前行程内、可与默认 1500 µs 明确区分的值，确认保存。关闭地面站自动连接，仪器先开始采集，再给板上电。保持上位机不发命令，记录首枚完整脉冲及随后 1 秒的波形，然后连接地面站。重复冷启动 3 次。 | 每次均能独立启动，身份正确、`locked=1`。各通道的首枚有效脉冲和稳定脉宽均应与本机保存的 trim 一致，按仪器精度判读。若先出现默认脉宽，保存原始波形并登记异常，即使随后已恢复。 |
| 2. 控制与辅助采集 | 保持锁定，缓慢倾斜再放平板子，拨动遥控通道。查看飞行页、遥控器页及所接辅助传感器。接有 MT6701 时同步转动磁编码器，观察锁定状态下 OLED 刷新与角度更新。 | 姿态、遥控和辅助测量分别响应对应动作，锁定 PWM 始终保持 trim。采用有效身份和有效 IMU 校准的板，再在动力断开的条件下，用按键 36 长按解锁、再上锁，确认状态与五路输出回到锁定值。 |
| 3. 500 Hz 基线 | 确认身份有效、测试卡可写，保持锁定，正常记录 CSV。等诊断参数保存后，记录起点计数，连续运行 5 分钟，再记录终点。 | `Δcycles / 实际秒数` 接近 500，5 分钟约 150000 轮。建议 `missed`、`intervals_ge_4ms`、`execution_gt_2ms`、`log_drops`、`log_write_errors` 的增量均为 0。保存起末诊断行与 CSV。 |
| 4. 参数保存与共享存储 | 保持记录和诊断，修改一次无机械影响的 SD 参数，如切换 `usb_actuator_output_debug`，观察保存通知。保持锁定，再从 USB 地面站下载一份已有日志，关闭文件窗口后继续运行至少 1 分钟。分别记录保存、下载、恢复三个阶段。 | 变更能读回，冷启动后仍生效。下载文件可读，关闭会话后继续写日志。下载期间固件主动暂停新日志，CSV 可以有时间缺口；健康卡上 `log_write_errors`、`log_drops` 应无新增。控制周期计数持续推进。 |
| 5. 持续运行 | 正常负载下继续运行 30 分钟，期间多次打开地面站页面、操纵遥控、断开并重连 USB 数据会话，保持板子供电。 | 无意外重启、卡死或异常解锁，重连后能读到原身份，`cycles` 延续。记录五个常驻任务的最小剩余栈，以及期间最高执行时间、最大周期间隔和最长 IMU 至 PWM 写入时间。 |

**首脉冲单独验收。** 当前固件依次调用五次 `Servo::attach()`，再写五路锁定值。Teensy Servo 驱动会在挂接时设置默认脉宽，实际首脉冲要从上电波形判定。舵机驱动名义刷新间隔约 20 ms，500 Hz 是控制软件更新指令的频率。`imu_pwm_us` 量到写入驱动返回，物理输出以仪器波形为准。[飞控执行器初始化](../src/actuators/actuator_output.cpp) · [Teensy Servo 实现](https://github.com/PaulStoffregen/Servo/blob/master/Servo.cpp) · [Servo 刷新间隔](https://github.com/PaulStoffregen/Servo/blob/master/Servo.h)

## 第二轮：启动交接与扩展工况

| 项目 | 操作和判据 |
| --- | --- |
| 调试版启动顺序 | 使用 VS Code 的 TeensyDebug 启动项和匹配的 ELF。首停 `initializeFirmwareDebug()` 后，在 `startupTask()` 的 `initializeCommandLinks()` 行核对已加载的身份与 trim。在 `xTaskResumeAll()` 行确认五个业务句柄均非空。在 `controlTask()` 首轮确认参数仍为保存值，并在 `Startup` 的 `vTaskDelete(nullptr)` 行确认执行到退出点。恢复调度后 `Control` 可以先于 `Startup` 自删运行，这是优先级调度的正常结果。移除断点、继续运行，确认普通 USB 口地面站可用。切回发布固件并冷启动后再测时序。[启动入口](../src/main.cpp) · [双串口调试](../tools/teensy_debug/README.md) |
| 无 SD 卡冷启动 | 断电后取出测试卡，再上电。预期参数服务报告 `NO_SD`，地面站可连、系统保持锁定，且能提供实时数据和诊断。此时来自 SD 的 trim 可能回退，保持动力断开。断电装回原测试卡，验证保存的参数和日志恢复。 |
| 接收机停帧与恢复 | 保持飞控锁定，让接收机停止向飞控发送有效帧，保留飞控供电。用 `GCS DATA` 观察 `radio_valid` 是否在数据过期后转为 0、恢复收帧后回到 1，核对遥控通道重新跟随摇杆、锁定 PWM 保持。若接收机在遥控器关机后仍发送有效保持帧，应另测真正的输入停帧。 |
| 有 X6 / 第二块板 | X6 与 USB 使用不同请求 ID 同时读取状态，核对两端收到各自的事务回复。两块板另核对各自身份与相邻节点状态，断开再恢复机间数据线，观察对应有效性标志变化和本机周期计数。单板和仅 USB 的台架将缺少的项目记为「未测」。 |
| 标定与 EEPROM 写入 | 在专用测试板或已备份标定的板上，锁定并静置，单独发起一次内置 IMU 标定。观察进度、锁定 PWM、保存通知，重启核对校准状态。把 Flash 写入窗口的周期计数增量单独记录。EEPROM 对应的 Flash 操作可能屏蔽中断。 |

## 记录与收尾

- 每个工况保存起末两条时序诊断和对应串口原始记录。`missed` 表示调度器跳过的释放次数，`intervals_ge_4ms` 表示相邻两轮的起点间隔至少 4 ms，`execution_gt_2ms` 表示单轮执行超过 2 ms。区间内的新增事件用终值减初值。
- `max_period_us`、`max_execution_us`、`max_imu_pwm_us` 是本次启动以来的峰值。要比较每个独立工况的峰值，应分别冷启动。五个 `stack_words` 依次对应 Control、Links、Aux、Parameters、Storage，每字 4 字节，记录历史最小余量。USB 下载占用回复通道时诊断行可能暂缺，可比较会话前后计数或由 X6 旁路记录。[时序统计](../src/system/flight_clock.cpp) · [诊断字段](../src/diagnostics/debug_print.cpp)
- 建议每项登记：板号及固件哈希、工况及持续时间、计数增量、峰值、五项栈余量、观测结果、证据文件名。优先留存异常首脉冲、一次正常冷启动、负载前后诊断及相应 CSV。
- 出现意外解锁、锁定脉宽不符、反复重启或卡死时，保持动力断开，先保留波形与日志，暂停解锁和后续带载项目。完成后恢复原 trim 和调试开关，等待保存，冷启动核对恢复值。
