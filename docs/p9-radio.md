# CUAV P9 数传与 CoFly 地面站（历史记录）

> 当前使用 3DR X6，见 [X6 接入说明](x6-radio.md)。本文仅保留 P9 历史，其供电、驱动和配置命令不适用于 X6。

本版本使用 P9 的透明串口传输，沿用仓库 `tools/ground_station` 的 `GCS` / `PARAM` 文本协议，不需要 MAVLink 或 P9 专用 Arduino 库。USB 直连继续可用；两条链路独立解析请求和发送响应，不转发 USB 调试输出。

## 接线与供电

| P9 Data 信号 | Teensy 4.1 | 用途 |
| --- | --- | --- |
| TX | 34 / RX8 | 接收无线命令 |
| RX | 35 / TX8 | 发送回复 |
| GND | GND | 共地 |
| RTS、CTS | 不接 | 三线串口，不使用硬件流控；确认 P9 配置不要求握手 |
| 5V+ | 不接 | 不为 P9 或 Teensy 供电 |

P9 Data 插座定义见 [官方接口图](references/cuav-p9/p9-pinouts.png)。按图中天线在左、Data 插座朝向观察者的方向，信号从左到右为 `5V+ / RX / TX / RTS / CTS / GND`；线束另一面观察会相反，应核对实际针位，不依赖线色。

P9 UART 为 3.3V CMOS TTL，可与 Teensy 直接连接；Teensy 信号脚不耐受 5V。P9 两端均需从各自 XT30 电源口独立供电，官方工作电压 12–60V，要求电源输出能力 >2.5A。飞控整合线中的 5V 不能给 P9 供电。安装天线后再上电。

来源：[CUAV 产品参数](https://doc.cuav.net/data-transmission/p9-radio/en/)、[P9 中文手册](references/cuav-p9/p9-user-manual-cn.pdf)、[PJRC 串口表](https://www.pjrc.com/teensy/td_uart.html)。

## 使用步骤

1. 构建并烧录 `.pio/build/teensy41/firmware.hex`。`beginTelemetryLink()` 在 setup 中初始化 Serial8，主循环每周期服务 USB 和 P9；无效飞机身份或待重启锁定分支也能通信。
2. 按上表连接天空端；两端 P9 接好天线、独立供电并确认配对。先给地面端供电，再给天空端供电。工厂已配对的模块通常无需重设。
3. 地面端用 Type-C 数据线连接电脑。如无 COM 口，使用 [CUAV 提供的 CP2102 驱动包](references/cuav-p9/radio-drive2102.rar)，解压后根据系统选择安装程序。资源下载不等于已安装驱动。
4. 启动 `tools/ground_station/dist/CoFlyGroundStation.exe`，或运行 `tools/ground_station/start.cmd`。在“通讯连接”选择 **CUAV P9**、地面端 COM 口和 **57600**，点击连接。切换连接方式会带入默认波特率；如果更改过模块配置，需要同步匹配。
5. 自动识别固件后，飞行页显示实时数据和构型；参数读取/修改、参数文件导入、遥控校准和重启沿用原协议及原锁定/存储约束。所有请求按链路返回。查看全机构型应连接 A 主机的 P9。
6. USB 直连时选 **USB** 和 Teensy COM 口，默认 921600。自动连接仍仅识别 Teensy USB，不扫描 P9；P9 需要手动选择。

固件波特率集中在 `src/config/serial_config.h` 的 `TELEMETRY_BAUD = 57600`，格式 8N1。电脑侧关闭 RTS/CTS、DSR/DTR 和 XON/XOFF 流控。P9 配置应使用透明传输、匹配的网络及串口速率；不要将 AT 配置命令发给正常运行的飞控。

需要重新配对/修改参数时，参考 [CUAV 配置教程](https://doc.cuav.net/data-transmission/p9-radio/en/config.html)：`AT&V` 查询配置，`ATS102=2` 表示 57600，`AT&W` 保存，`ATA` 回到通信模式。进入配置模式的方法及主从恢复命令以官方教程为准；固件不会自动重置无线模块。

## 原 telemetry 的内容与本次替换

旧实现以 Serial8 / 115200 每秒 5 次发送 19 字节：`55 71` 帧头、六个相邻 IMU 滚转差 AB/AC/BD/CE/DF/EG、等效滚转和本机俯仰、末字节累加校验。八个角度乘 10 后转 int16，以低字节在前发送。原注释写 10Hz，但实际变量是 5Hz；初始化和发送入口均被注释。

仓库地面站不解析该二进制帧，而是请求 `GCS CAPS/DATA/CONFIG id` 并接收 `@COFLY` TSV 文本。本次移除旧主动二进制输出，由 `telemetry()` 轮询与 USB 共用业务逻辑的 P9 服务；已有 DATA 提供本机姿态/角速度/加速度/空速/遥控输入，CONFIG 提供相对角和各机滚转/俯仰。等效滚转不再作为旧二进制字段单独广播。

旧 `getairdata()` 也占用 Serial8，以 `AA 55` 帧头读取外部气动数据，会吞掉文本命令且可能阻塞。本次删除该读取函数及主循环入口。`airdata` 结构和原日志字段保留，但不再由 Serial8 更新，不应把这些字段当作有效外部气动测量；MS4525 空速采样不受影响。如需接入外部气动数据，应另行分配串口和协议。

## 链路行为与限制

- USB/P9 各自拥有 767 字节命令缓冲、回复分片位置和参数读取快照；并行读取不会交叉响应。两端修改的是同一组实时参数，使用时避免同时编辑同一参数。
- 每链路每周期最多读 64 字节、发送 64 字节，按可写空间提交，不等待整帧装入串口缓冲。P9 增加 1024 字节收发缓冲；没有无线请求时不主动发送测量包。
- 地面站按原逻辑最高 5Hz 请求数据，飞行页交替读取 DATA 与 CONFIG，实际刷新率受无线延迟和串口带宽影响。超过两秒无有效数据清空读数。
- 参数列表读取以八秒无进展为超时，每条合法 BEGIN/VALUE 回复刷新期限，允许总读取时间超过八秒。断链/超时不自动重试写参数或重启；写入结果未确认时需要重读核对。
- UART 没有 USB 的连接状态。未完成命令超过两秒会清除，长命令或无效字符丢弃到行尾。地面站断开电脑端口并不会自动通知飞控无线链路已断开。
- 重启等待两条链路的待发文本都提交后进入原 250ms 延迟。接收端没有独立应用层确认，收到 REBOOTING 后再等待重连。
